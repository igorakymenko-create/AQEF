# Appendix B — AQEF JSON Schema

This appendix specifies the validation rules a conformant JSON Schema MUST enforce for
AQEF configuration documents. It restates, in schema-oriented terms, the structures
defined by Volume II (Domain Model), Volume VII (Contract Language), and Appendix A
(YAML Specification). It does not provide a complete, machine-readable JSON Schema
artifact — that artifact SHOULD be generated by a conformant implementation's own
tooling from this prose specification (see Scope, §6).

Each section describes a schema type: its properties, their types, required/optional
status, enumerated values, and cross-type validation rules that a schema alone cannot
enforce but an implementation MUST.

## B.2 — Property Constraints

For each type, the schema MUST enforce the following.

**Project**
```
properties:
  name:          { type: string, minLength: 1 }                    # REQUIRED
  environments:  { type: array, items: Environment, minItems: 1 }  # REQUIRED
  suites:        { type: array, items: Suite }                    # OPTIONAL
  execution:     { $ref: ExecutionConfig }                         # OPTIONAL
  datasets:       { type: array, items: Dataset }                  # OPTIONAL
  defect_classes: { type: array, items: DefectClassConfig }        # OPTIONAL
  contracts:      { type: array, items: { oneOf: [Contract, string] } }  # OPTIONAL
  quality_gates:  { type: array, items: QualityGate }              # OPTIONAL
```

**DefectClassConfig**
```
properties:
  name:               { type: string, minLength: 1 }                    # REQUIRED
  difficulty_prior:   { oneOf: [ { type: number, minimum: 0.0,
                        maximum: 1.0 },
                        { type: string, const: not_established } ] }    # OPTIONAL
  prior_basis:        { type: integer, minimum: 1 }                     # CONDITIONAL
  prior_source:       { type: string, enum: [reference_oracles,
                        human_reviewer] }                               # CONDITIONAL
  reference_oracles:  { type: array, items: JudgeConfig }               # OPTIONAL
```

*Cross-field rule:* `prior_basis` and `prior_source` are REQUIRED when `difficulty_prior`
is a number. An absent `difficulty_prior` is equivalent to `"not_established"`; a schema
MUST NOT default it to `0.0`.

**Environment**
```
properties:
  name:                { type: string, minLength: 1 }        # REQUIRED
  model_version:       { type: string, minLength: 1 }        # REQUIRED
  prompt_version:      { type: string, minLength: 1 }        # REQUIRED
  tool_configuration:  { oneOf: [ToolConfig, null] }         # REQUIRED
  action_boundary:     { $ref: ActionBoundary }              # CONDITIONAL
  infra_target:        { type: string, minLength: 1 }        # REQUIRED
```

*Cross-field rule:* `action_boundary` is REQUIRED when `tool_configuration` is not null.

**ActionBoundary**
```
properties:
  enforced:  { type: boolean }                                   # REQUIRED
  entries:   { type: array, items: BoundaryEntry, minItems: 1 }  # REQUIRED
```

**BoundaryEntry**
```
properties:
  target:    { type: string, minLength: 1 }                      # REQUIRED
  kind:      { type: string, enum: [stub, sandbox, real] }       # REQUIRED
  tripwire:  { type: boolean, default: false }                   # OPTIONAL
```

*Cross-field rule:* `tripwire: true` is valid only when `kind` is `stub`.

**Suite**
```
properties:
  name:           { type: string, minLength: 1 }                         # REQUIRED
  scenarios:      { type: array, items: Scenario, minItems: 1 }          # REQUIRED
  contracts:      { type: array, items: { oneOf: [Contract, string] } }  # OPTIONAL
  quality_gates:  { type: array, items: QualityGate }                    # OPTIONAL
  execution:      { $ref: ExecutionConfig }                              # OPTIONAL
```

**Scenario**
```
properties:
  name:             { type: string, minLength: 1 }        # REQUIRED
  contract:         { oneOf: [Contract, string] }         # CONDITIONAL
  prompt:           { $ref: PromptDef }                   # CONDITIONAL
  dataset:          { type: string, pattern: "^.+@.+$" }  # OPTIONAL (name@version)
  variables:        { type: object }                      # OPTIONAL
  seeded_control:   { $ref: SeededControlConfig }          # OPTIONAL
  evidence:         { $ref: FixedEvidence }                # CONDITIONAL
```

*Cross-field rule:* `dataset` and `variables` are mutually exclusive. A schema SHOULD
enforce this via a `oneOf` containing three shapes: dataset-only, variables-only, and
neither. `contract` is REQUIRED unless the Project or Suite supplies `contracts`
(checked at load time, B.3). `prompt` is REQUIRED unless `dataset` names a
`production_replay` Dataset (checked at load time, B.3).

**PromptDef**
```
properties:
  template:  { type: string, minLength: 1 }   # REQUIRED
```

**SeededControlConfig**
```
properties:
  defect_class:      { type: string, minLength: 1 }                    # REQUIRED
  difficulty_prior:  { oneOf: [ { type: number, minimum: 0.0,
                       maximum: 1.0 },
                       { type: string, const: not_established } ] }    # OPTIONAL
  planted_defect:    { }                                               # REQUIRED
  confirmed_by:      { type: string, enum: [validator, human_reviewer,
                       construction] }                                 # REQUIRED
  confirmation:      { $ref: Constraint }                              # CONDITIONAL
  generator:         { type: string }                                  # OPTIONAL
```

Note: an absent `difficulty_prior` is equivalent to `"not_established"`, not to `0.0`.
A schema MUST NOT default this field to `0.0`.

*Cross-field rules:* `confirmation` is REQUIRED when `confirmed_by` is `validator` and
MUST NOT appear otherwise. When `confirmed_by` is `construction`, the Scenario MUST carry
`evidence` and MUST NOT carry `prompt`, `dataset`, or `variables`.

**FixedEvidence**
```
properties:
  conversation:      { }                                  # REQUIRED
  artifacts:         { type: object }                     # OPTIONAL
  source_execution:  { type: string, minLength: 1 }       # OPTIONAL
```

**Contract**
```
properties:
  name:          { type: string }                       # CONDITIONAL
  constraints:   { type: array, items: Constraint }      # OPTIONAL
  expectations:  { type: array, items: Expectation }     # OPTIONAL
  policies:      { $ref: Policies }                      # OPTIONAL
  extends:       { type: array, items: string }          # OPTIONAL
```

*Cross-field rule:* at least one of `constraints` or `expectations` MUST be non-empty.
`name` is REQUIRED when the Contract is defined as a reusable artifact, OPTIONAL when
inline.

**Constraint**
```
properties:
  validator:  { type: string, minLength: 1 }         # REQUIRED
  target:     { type: string, minLength: 1 }         # REQUIRED
  expected:   { }                                    # REQUIRED
  veto:       { type: boolean, default: false }      # OPTIONAL
  id:         { type: string, minLength: 1 }         # OPTIONAL
  dimension:  { type: string, enum: [functional, semantic,
                operational, safety] }               # OPTIONAL (default by validator type)
  defect_classes: { type: array, items: { type: string } }  # OPTIONAL
```

Note: the `expected` field's shape is validator-specific. A schema MAY use a permissive
type here and defer structural validation to the Validator Engine, or MAY define
per-validator sub-schemas via a discriminator on the `validator` field.

**Expectation**
```
properties:
  criteria:               { type: string, minLength: 1 }              # REQUIRED
  judge:                  { $ref: JudgeConfig }                       # CONDITIONAL
  multi_judge:            { $ref: MultiJudgeConfig }                  # CONDITIONAL
  human_reviewer:         { $ref: HumanReviewerConfig }                # CONDITIONAL
  confidence_threshold:   { type: number, minimum: 0.0, maximum: 1.0 } # CONDITIONAL
  review_timeout:         { type: string }                             # OPTIONAL
  on_timeout:             { type: string, enum: [block, escalate],
                            default: block }                           # OPTIONAL
  id:                     { type: string, minLength: 1 }               # OPTIONAL
  dimension:              { type: string, enum: [functional, semantic,
                            operational, safety], default: semantic }  # OPTIONAL
  defect_classes:         { type: array, items: { type: string } }     # OPTIONAL
```

*Cross-field rules:*
- Exactly one of `judge`, `multi_judge`, or `human_reviewer` MUST be present.
- `confidence_threshold` is REQUIRED when `judge` or `multi_judge` is present (a Judge
  Result always carries Confidence). It is OPTIONAL when `human_reviewer` is present,
  since a Human Reviewer Result MAY carry no Confidence value at all (Volume II).

**HumanReviewerConfig**
```
properties:
  role:                { type: string, minLength: 1 }   # REQUIRED
  captures_confidence:  { type: boolean, default: false } # OPTIONAL
```

**JudgeConfig**
```
properties:
  model:               { type: string, minLength: 1 }                          # REQUIRED
  confidence_source:   { type: string, enum: [self_rating, token_probability,
                         agreement] }                                          # REQUIRED
```

**MultiJudgeConfig**
```
properties:
  purpose:    { type: string, enum: [independence, stability] }   # REQUIRED
  judges:     { type: array, items: JudgeConfig, minItems: 2 }     # CONDITIONAL
  judge:      { $ref: JudgeConfig }                                # CONDITIONAL
  samples:    { type: integer, minimum: 2 }                        # CONDITIONAL
  consensus:  { $ref: ConsensusConfig }                            # REQUIRED
```

*Cross-field rules:*
- When `purpose` is `independence`: `judges` REQUIRED, `judge`/`samples` MUST NOT
  appear.
- When `purpose` is `stability`: `judge` and `samples` REQUIRED, `judges` MUST NOT
  appear.

**ConsensusConfig**
```
properties:
  method:           { type: string, minLength: 1 }                       # REQUIRED
  threshold:        { oneOf: [ { type: string, enum: [majority, unanimous] },
                      { type: number, exclusiveMinimum: 0.5,
                        maximum: 1.0 } ] }                               # OPTIONAL
  min_agreement:    { type: number, minimum: 0.0, maximum: 1.0 }         # OPTIONAL
  on_disagreement:  { type: string, enum: [human_review, fail, flag],
                      default: human_review }                            # OPTIONAL
  min_qualified:    { type: integer, minimum: 1 }                        # OPTIONAL
```

*Cross-field rule:* `threshold` MAY appear only when `method` is `voting`; absent, it
defaults to `majority`. A numeric threshold MUST be a number, not a string: `0.75` is
valid, `"0.75"` is not.

**Dataset**
```
properties:
  name:           { type: string, minLength: 1 }                              # REQUIRED
  version:        { type: string, minLength: 1 }                              # REQUIRED
  source:         { type: string, enum: [static, synthetic, generated,
                    production_replay] }                                      # REQUIRED
  rows:           { type: array, items: Row }                                 # CONDITIONAL
  generator:      { $ref: GeneratorConfig }                                   # CONDITIONAL
  capture:        { $ref: CaptureConfig }                                     # CONDITIONAL
  base_dataset:   { type: string }                                           # OPTIONAL
  mechanisms:     { type: array, items: MechanismConfig }                     # OPTIONAL
```

*Cross-field rules:*
- When `source` is `static`: `rows` REQUIRED.
- When `source` is `generated`: `generator` REQUIRED.
- When `source` is `production_replay`: `capture` REQUIRED.

**ExecutionConfig**
```
properties:
  timeout:          { type: string }                     # OPTIONAL
  retry:            { $ref: RetryConfig }                 # OPTIONAL
  scheduling:       { type: string }                      # OPTIONAL
  parallelization:  { type: integer, minimum: 1 }         # OPTIONAL
  on_seeded_control_miss: { type: string, enum: [skip_class, halt_run],
                            default: skip_class }         # OPTIONAL
```

**RetryConfig**
```
properties:
  max_attempts:  { type: integer, minimum: 1 }                    # REQUIRED
  on:            { type: string, const: infrastructure_failure }  # REQUIRED
```

Note: the `on` field is constrained to `infrastructure_failure` only. A schema MUST
reject any other value. Retrying after a genuine Response is strictly prohibited
(Volume III).

**QualityGate**
```
properties:
  name:                { type: string, minLength: 1 }               # REQUIRED
  aggregate:           { type: string, minLength: 1 }                # REQUIRED
  threshold:           { oneOf: [number, object] }                   # REQUIRED
  compare_against:     { type: string }                              # OPTIONAL
  min_basis:           { $ref: MinBasis }                            # OPTIONAL
  on_failure:          { type: string, enum: [block_release, warn] } # REQUIRED
  override_requires:   { type: string }                              # OPTIONAL
```

**MinBasis**
```
properties:
  results:    { type: integer, minimum: 1 }   # OPTIONAL
  scenarios:  { type: integer, minimum: 1 }   # OPTIONAL
```

*Cross-field rule:* at least one of `results` or `scenarios` MUST be present.

**Baseline**
```
properties:
  scenario:       { type: string, minLength: 1 }          # REQUIRED
  environment:    { type: string, minLength: 1 }          # REQUIRED
  execution_id:   { type: string, minLength: 1 }          # REQUIRED
  approved_by:    { type: string, minLength: 1 }          # REQUIRED
  approved_at:    { type: string, format: date-time }     # REQUIRED
  approval_role:  { type: string, minLength: 1 }          # REQUIRED
```

**ReleaseDecision**
```
properties:
  id:                  { type: string, minLength: 1 }                    # REQUIRED
  project:             { type: string, minLength: 1 }                    # REQUIRED
  environment:         { type: string, minLength: 1 }                    # REQUIRED
  suite:               { type: string, minLength: 1 }                    # REQUIRED
  execution_batch_id:  { type: string, minLength: 1 }                    # REQUIRED
  gates:               { type: object, additionalProperties: GateResult,
                         minProperties: 1 }                              # REQUIRED
  decision:            { type: string, enum: [approved, rejected,
                         overridden] }                                   # REQUIRED
  approved_by:         { type: string, minLength: 1 }                    # REQUIRED
  approved_at:         { type: string, format: date-time }               # REQUIRED
  approval_role:       { type: string, minLength: 1 }                    # REQUIRED
  report_id:           { type: string, minLength: 1 }                    # REQUIRED
  snapshot_id:         { type: string, minLength: 1 }                    # REQUIRED
  release_policy:      { type: string, minLength: 1 }                    # CONDITIONAL
  notes:               { type: string }                                  # OPTIONAL
```

**GateResult**
```
properties:
  id:         { type: string, minLength: 1 }                             # REQUIRED
  status:     { type: string, enum: [pass, fail] }                       # REQUIRED
  blocking:   { type: boolean }                                          # REQUIRED
  reasons:    { type: array, minItems: 1, uniqueItems: true,
                items: { type: string, enum: [threshold, insufficient_basis,
                non_actionable_results, seeded_control_miss,
                stale_results] } }                                       # CONDITIONAL
  value:      { oneOf: [ { type: number },
                { type: object, additionalProperties: { type: number } },
                { type: string, const: not_computed } ] }                # REQUIRED
  threshold:  { oneOf: [number, object] }                                # REQUIRED
  basis:      { $ref: Basis }                                            # REQUIRED
  override:   { type: string, minLength: 1 }                             # CONDITIONAL
```

*Cross-field rules:* `reasons` is REQUIRED when `status` is `fail` and MUST NOT appear
when it is `pass`; it lists every reason that applies. `override` MAY appear only when `status` is `fail` and `blocking` is
`true`.

**Basis**
```
properties:
  results:         { type: integer, minimum: 0 }                         # REQUIRED
  not_actionable:  { type: integer, minimum: 0 }                         # REQUIRED
  scenarios:       { type: integer, minimum: 0 }                         # REQUIRED
  executions:      { type: integer, minimum: 0 }                         # REQUIRED
  min_basis_met:   { oneOf: [ { type: boolean },
                     { type: string, const: not_declared } ] }           # REQUIRED
```

**Snapshot**
```
properties:
  id:             { type: string, minLength: 1 }                         # REQUIRED
  captured_at:    { type: string, format: date-time }                    # REQUIRED
  project:        { type: string, minLength: 1 }                         # REQUIRED
  suites:         { type: array, items: { type: string }, minItems: 1 }  # REQUIRED
  environments:   { type: object, additionalProperties: Environment }    # REQUIRED
  contracts:      { type: object,
                    additionalProperties: { type: string } }             # REQUIRED
  inline_contracts: { type: object, additionalProperties:
                      { type: array, items: Contract } }                 # REQUIRED
  quality_gates:  { type: array, items: QualityGate }                    # REQUIRED
  baselines:      { type: array, items: { type: string } }               # OPTIONAL
  release_label:  { type: string }                                       # OPTIONAL
```

**ReleasePolicy**
```
properties:
  id:                { type: string, minLength: 1 }                      # REQUIRED
  project:           { type: string, minLength: 1 }                      # REQUIRED
  suites:            { type: array, items: { type: string }, minItems: 1 }  # REQUIRED
  environments:      { type: array, items: { type: string }, minItems: 1 }  # REQUIRED
  service_accounts:  { type: array, items: { type: string }, minItems: 1 }  # REQUIRED
  approved_by:       { type: string, minLength: 1 }                      # REQUIRED
  approval_role:     { type: string, minLength: 1 }                      # REQUIRED
  approved_at:       { type: string, format: date-time }                 # REQUIRED
  revoked_at:        { type: string, format: date-time }                 # OPTIONAL
  revoked_by:        { type: string, minLength: 1 }                      # CONDITIONAL
```

*Cross-field rule:* `revoked_by` is REQUIRED when `revoked_at` is present.

## B.3 — Cross-Type Validation Rules

The following rules cannot be expressed within a JSON Schema alone and MUST be enforced
by a conformant implementation at configuration load time:

| Rule | Source | Description |
|---|---|---|
| Independent Oracle — identity | Volume I, Ch. 3 | A JudgeConfig's `model` MUST NOT be identical to the Environment's `model_version` (same weights/decision process as the subject). |
| Independent Oracle — family | Volume I, Ch. 3 | A JudgeConfig's `model` SHOULD NOT be from the same model family as the Environment's `model_version`, where this can be avoided. |
| Contract non-empty | Volume VII | A Contract with zero Constraints and zero Expectations is invalid. |
| Effective Contract | Volume VII | For every Scenario in every Suite, the composition of the Project's `contracts`, the Suite's `contracts`, and the Scenario's `contract` MUST contain at least one clause. A Scenario MAY omit `contract` only when the Project or Suite supplies one. A lower level MUST NOT remove or weaken a clause contributed by a higher one. Two clauses are the same clause only when they declare the same `id`; the same `id` with differing content is a composition conflict. |
| Gate name uniqueness | Volume I, Ch. 6 | A Quality Gate name MUST be unique across a Project's `quality_gates` and those of all its Suites. |
| Prompt presence | Volume II; Volume III | A Scenario MUST carry `prompt` unless its `dataset` is a `production_replay` Dataset or it carries `evidence`. Every Variable a `prompt.template` references MUST be supplied by the Scenario's `variables` or every row of its Dataset. |
| Consensus threshold | Volume VI | `threshold` is valid only with `method: voting`. Votes are counted against `panel.counted` (or samples); a verdict requires at least ⌈threshold × count⌉ matching votes. |
| Expectation Oracle exclusivity | Volume VII | Exactly one of `judge`, `multi_judge`, `human_reviewer` MUST be present on an Expectation; `confidence_threshold` is REQUIRED for the first two and OPTIONAL for the third. |
| Dataset version immutability | Volume IV | Two configurations referencing the same Dataset name + version MUST resolve to identical rows. |
| Retry scope | Volume III | RetryConfig MUST NOT trigger on Result-level failures, only infrastructure failures. |
| Baseline reproducibility | Volume X | A Baseline MUST reference a Dataset version and Contract version that are still recoverable. |
| Composition conflict surfacing | Volume VII | When composition, by `extends` or across Project, Suite, and Scenario, yields two clauses with the same `id` and differing content, the implementation MUST surface the conflict, not silently resolve it. |
| Multi-Judge purpose consistency | Volume VI | An independence-mode MultiJudge with judges from the same model family SHOULD produce a warning. |
| Result disposition validity | Appendix C §C.7 | `verdict` MUST be `null` when `disposition` is `awaiting_review`, `oracle_unavailable`, or `not_assessed`, and MUST be `pass` or `fail` otherwise. `confidence` MUST NOT be bare `null` under any disposition. |
| Seeded Control invalidation scope | Volume VIII; Appendix C §C.3 | A missed Seeded Control invalidates only the Results its Oracle produced in the same run sharing its `defect_class`, by default. Full-run invalidation requires a Project to declare it explicitly, with a recorded, non-empty reason. |
| Difficulty prior provenance | Volume VIII | A `difficulty_prior` (on a DefectClassConfig or a SeededControlConfig) MUST be established from reference Oracles independent of the Oracle(s) the controls test, or from Human Reviewers, and MUST NOT be set or updated from the outcome of the Oracle(s) under test. |
| Seeded Control confirmation | Volume VIII; Appendix C §C.3 | A control's outcome MUST be reported as `invalid` for that run, not as `caught` or `missed`, unless the presence of its planted defect in the Evidence the Oracle received was confirmed by its declared method: its `confirmation` passed (`validator`), a Human Reviewer's confirmation is recorded (`human_reviewer`), or it carries `evidence` (`construction`). |
| Fixed Evidence scope | Volume III; Volume VIII | `evidence` MAY appear only on a Scenario whose `seeded_control.confirmed_by` is `construction`. An Execution of such a Scenario MUST NOT invoke the subject. |
| Defect class reference | Volume VIII | Where a Project declares `defect_classes`, every `seeded_control.defect_class` and every clause-level `defect_classes` entry SHOULD name a declared class. |
| Panel reporting | Volume VI; Appendix C §C.7 | A Result produced by a Multi Judge configuration MUST carry `panel`. Below `min_qualified` (or below the full panel when it is absent), the panel's Results for the affected clauses MUST be `not_assessed`. |
| Aggregate Basis reporting | Volume I, Ch. 6; Appendix C §C.3 | Every aggregate a Quality Gate reads MUST be reported with its Aggregate Basis. Where `min_basis` is declared and not met, the Gate MUST NOT pass, and the reason MUST be reported as insufficient basis, not as a threshold failure. |
| Action Boundary presence | Volume III | An Environment with a non-null `tool_configuration` MUST declare `action_boundary`. |
| Boundary attempt capture | Volume III; Volume V | Every attempt to reach outside an Action Boundary, and every Tripwire touch, MUST be captured as an Artifact whether or not it was blocked, and MUST fail a bound Boundary Validator. |
| Unenforced boundary reporting | Volume III; Volume XI | An Environment declaring `enforced: false` MUST be identified in every Report whose scope includes it. |
| Deletion referential integrity | Appendix C §C.8 | `DELETE` on an Environment, Dataset, or Contract still referenced by a Baseline, Snapshot, or Report MUST be rejected or preserved as a frozen record, never silently broken. |
| Result resolution | Volume I, Ch. 6; Appendix C §C.7 | `resolves` MUST reference the current effective Result for the same `execution` and `clause`, and that Result's effective state MUST NOT be `actionable`. A second Result resolving the same Result MUST be rejected. Resolvers: a Human Reviewer Result (for `inconclusive`, or a panel's unresolved Result); a requalified Oracle's Result (for invalidated or `not_assessed`); a Result from the same `oracle` (only for `oracle_unavailable`). |
| Effective Result | Volume I, Ch. 6 | Aggregation and Quality Gates read only the effective Result per Execution and clause, by its effective state. A resolved Result MUST NOT be counted again, including in `basis.not_actionable`. |
| Invalidation is derived | Volume I, Ch. 6; Volume VIII | A missed Seeded Control MUST NOT change any recorded Result. Its effect is derived from `seeded_control_results`: the affected effective Results have effective state `invalidated`, with one `invalidated_by` entry per missed control that reaches them. |
| Requalification covers every invalidation | Volume I, Ch. 6; Volume VIII | A requalified Oracle's Result MAY resolve an invalidated Result only if that Oracle has been requalified for every `defect_class` in the Result's `invalidated_by`. |
| Validator unavailable | Volume V; Appendix C §C.7 | A Validator that cannot complete its check MUST produce `oracle_unavailable`, never `fail`, and Validation for that Execution has not passed. |
| Gate reasons | Volume I, Ch. 6; Appendix A §A.12 | A failed GateResult MUST list every applicable reason. A Gate whose aggregate includes an effective Result that is not `actionable` MUST fail, with `non_actionable_results` or `seeded_control_miss`. |
| Gate Result override | Volume XII | An `override` MUST reference an approved `gate_override` record made for that GateResult, named by its `id`. One override record MUST NOT be referenced by more than one GateResult. |
| Release Decision coverage | Volume I, Ch. 6 | `gates` MUST contain a GateResult for every Quality Gate, blocking or advisory, applicable to the decision's scope. |
| Release Decision outcome | Volume I, Ch. 6; Volume XII | `decision: approved` requires every blocking GateResult to have `status: pass`; `decision: overridden` requires every blocking GateResult with `status: fail` to carry `override`. |
| Release Decision currency | Volume I, Ch. 6 | A Release Decision MUST NOT be recorded if any Contract (Reusable or inline), Quality Gate, or Environment in its scope differs from the configuration captured in the Snapshot named by `snapshot_id`. |
| Release Decision requires a Gate | Volume I, Ch. 6 | A Release Decision MUST NOT be recorded for a scope to which no Quality Gate applies. |
| Approval Permissions | Volume XII | A Baseline's `approval_role` MUST hold `baseline_approve`; a Release Decision's MUST hold `release_decide`. |
| Human approval | Volume XII | `baseline_approve` and `gate_override` MUST be approved by a Person. A `contract_define` applied by a Service Account MUST name the approving Person and reference the external review. |
| Automatic release | Volume XII | A Release Decision whose `approved_by` is a Service Account MUST carry `release_policy`, and its `decision` MUST be `approved` (every blocking GateResult `pass`, no `override`) or `rejected`. |
| Snapshot immutability | Volume X | A Snapshot MUST NOT be modified after `captured_at`. |
| Clause identity | Volume VII | A clause `id` MUST be unique within the Contract that declares it. |
| Dataset reference | Volume IV | A Scenario's `dataset` and a Dataset's `base_dataset` MUST name a version (`name@version`) that resolves to a Dataset in the Project's `datasets` or one registered through Appendix C §C.3. |
| Clause dimension | Volume I, Ch. 6 | A Constraint bound to a Custom Validator MUST declare `dimension`. |
| Stale Results | Volume I, Ch. 6 | A Gate whose aggregate includes a Result produced under an Environment, or for a clause of a Contract, other than the one the evaluation's Snapshot captures MUST fail, with `stale_results`. |
| Release policy | Volume XII | A Release Decision's `release_policy` MUST name a Release Policy in force when the decision is recorded, approved by a Person holding `release_decide`, that lists the acting Service Account and covers the decision's Suite and Environment. |
| Governed configuration change | Volume XII; Appendix C §C.5 | Creating or changing a `contract`, `contracts`, or `quality_gates` value, through whatever operation, is `contract_define`. |

## B.4 — Extensibility

A conformant schema MAY define additional properties beyond those specified here,
provided:

1. Additional properties do not conflict with the semantics of specified properties.
2. Additional properties are clearly namespaced or prefixed to avoid collision with
   future AQEF specification revisions.
3. A configuration that uses only specified properties remains valid under the
   extended schema.
