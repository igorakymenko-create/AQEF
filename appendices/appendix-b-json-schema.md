# Appendix B — AQEF JSON Schema

**Status:** confirmed (v0.1).

This appendix specifies the validation rules a conformant JSON Schema MUST enforce for
AQEF configuration documents. It restates, in schema-oriented terms, the structures
defined by Volume II (Domain Model), Volume VII (Contract Language), and Appendix A
(YAML Specification). It does not provide a complete, machine-readable JSON Schema
artifact — that artifact SHOULD be generated by a conformant implementation's own
tooling from this prose specification (see Scope, §6).

Each section describes a schema type: its properties, their types, required/optional
status, enumerated values, and cross-type validation rules that a schema alone cannot
enforce but an implementation MUST.

## B.1 — Schema Structure Overview

A conformant JSON Schema MUST define the following top-level types, each corresponding
to a Domain Model entity (Volume II):

| Schema Type | Appendix A Section | Volume |
|---|---|---|
| Project | A.1 | II |
| Environment | A.2 | II |
| Suite | A.3 | II |
| Scenario | A.4 | II |
| Contract | A.5 | VII |
| Constraint | A.5 | VII |
| Expectation | A.5 | VII |
| HumanReviewerConfig | A.5 | II, VI |
| Policies | A.5 | VII |
| JudgeConfig | A.6 | VI |
| MultiJudgeConfig | A.7 | VI |
| ConsensusConfig | A.7 | VI |

| Baseline | A.11 | X, XII |
| ReleaseDecision | A.12 | I, Ch. 6; XII |

## B.2 — Property Constraints

For each type, the schema MUST enforce the following.

**Project**
```
properties:
  name:          { type: string, minLength: 1 }                    # REQUIRED
  environments:  { type: array, items: Environment, minItems: 1 }  # REQUIRED
  suites:        { type: array, items: Suite }                    # OPTIONAL
  execution:     { $ref: ExecutionConfig }                         # OPTIONAL
```

**Environment**
```
properties:
  name:                { type: string, minLength: 1 }        # REQUIRED
  model_version:       { type: string, minLength: 1 }        # REQUIRED
  prompt_version:      { type: string, minLength: 1 }        # REQUIRED
  tool_configuration:  { oneOf: [ToolConfig, null] }         # REQUIRED
  infra_target:        { type: string, minLength: 1 }        # REQUIRED
```

**Suite**
```
properties:
  name:       { type: string, minLength: 1 }                  # REQUIRED
  scenarios:  { type: array, items: Scenario, minItems: 1 }   # REQUIRED
```

**Scenario**
```
properties:
  name:       { type: string, minLength: 1 }        # REQUIRED
  contract:   { oneOf: [Contract, string] }         # REQUIRED
  dataset:    { type: string }                      # OPTIONAL
  variables:  { type: object }                      # OPTIONAL
```

*Cross-field rule:* `dataset` and `variables` are mutually exclusive. A schema SHOULD
enforce this via a `oneOf` containing three shapes: dataset-only, variables-only, and
neither.

**Contract**
```
properties:
  name:          { type: string }                       # CONDITIONAL
  constraints:   { type: array, items: Constraint }      # OPTIONAL
  expectations:  { type: array, items: Expectation }     # OPTIONAL
  policies:      { $ref: Policies }                      # OPTIONAL
  extends:       { type: array, items: string }          # OPTIONAL
```

*Cross-field rule:* at least one of `constraints` or `expectations` MUST be non-empty.
`name` is REQUIRED when the Contract is defined as a reusable artifact, OPTIONAL when
inline.

**Constraint**
```
properties:
  validator:  { type: string, minLength: 1 }         # REQUIRED
  target:     { type: string, minLength: 1 }         # REQUIRED
  expected:   { }                                    # REQUIRED
  veto:       { type: boolean, default: false }      # OPTIONAL
```

Note: the `expected` field's shape is validator-specific. A schema MAY use a permissive
type here and defer structural validation to the Validator Engine, or MAY define
per-validator sub-schemas via a discriminator on the `validator` field.

**Expectation**
```
properties:
  criteria:               { type: string, minLength: 1 }              # REQUIRED
  judge:                  { $ref: JudgeConfig }                       # CONDITIONAL
  multi_judge:            { $ref: MultiJudgeConfig }                  # CONDITIONAL
  human_reviewer:         { $ref: HumanReviewerConfig }                # CONDITIONAL
  confidence_threshold:   { type: number, minimum: 0.0, maximum: 1.0 } # CONDITIONAL
  review_timeout:         { type: string }                             # OPTIONAL
  on_timeout:             { type: string, enum: [block, escalate],
                            default: block }                           # OPTIONAL
```

*Cross-field rules:*
- Exactly one of `judge`, `multi_judge`, or `human_reviewer` MUST be present.
- `confidence_threshold` is REQUIRED when `judge` or `multi_judge` is present (a Judge
  Result always carries Confidence). It is OPTIONAL when `human_reviewer` is present,
  since a Human Reviewer Result MAY carry no Confidence value at all (Volume II).

**HumanReviewerConfig**
```
properties:
  role:                { type: string, minLength: 1 }   # REQUIRED
  captures_confidence:  { type: boolean, default: false } # OPTIONAL
```

**JudgeConfig**
```
properties:
  model:               { type: string, minLength: 1 }                          # REQUIRED
  confidence_source:   { type: string, enum: [self_rating, token_probability,
                         agreement] }                                          # REQUIRED
```

**MultiJudgeConfig**
```
properties:
  purpose:    { type: string, enum: [independence, stability] }   # REQUIRED
  judges:     { type: array, items: JudgeConfig, minItems: 2 }     # CONDITIONAL
  judge:      { $ref: JudgeConfig }                                # CONDITIONAL
  samples:    { type: integer, minimum: 2 }                        # CONDITIONAL
  consensus:  { $ref: ConsensusConfig }                            # REQUIRED
```

*Cross-field rules:*
- When `purpose` is `independence`: `judges` REQUIRED, `judge`/`samples` MUST NOT
  appear.
- When `purpose` is `stability`: `judge` and `samples` REQUIRED, `judges` MUST NOT
  appear.

**Dataset**
```
properties:
  name:           { type: string, minLength: 1 }                              # REQUIRED
  version:        { type: string, minLength: 1 }                              # REQUIRED
  source:         { type: string, enum: [static, synthetic, generated,
                    production_replay] }                                      # REQUIRED
  rows:           { type: array, items: Row }                                 # CONDITIONAL
  generator:      { $ref: GeneratorConfig }                                   # CONDITIONAL
  capture:        { $ref: CaptureConfig }                                     # CONDITIONAL
  base_dataset:   { type: string }                                           # OPTIONAL
  mechanisms:     { type: array, items: MechanismConfig }                     # OPTIONAL
```

*Cross-field rules:*
- When `source` is `static`: `rows` REQUIRED.
- When `source` is `generated`: `generator` REQUIRED.
- When `source` is `production_replay`: `capture` REQUIRED.

**ExecutionConfig**
```
properties:
  timeout:          { type: string }                     # OPTIONAL
  retry:            { $ref: RetryConfig }                 # OPTIONAL
  scheduling:       { type: string }                      # OPTIONAL
  parallelization:  { type: integer, minimum: 1 }         # OPTIONAL
```

**RetryConfig**
```
properties:
  max_attempts:  { type: integer, minimum: 1 }                    # REQUIRED
  on:            { type: string, const: infrastructure_failure }  # REQUIRED
```

Note: the `on` field is constrained to `infrastructure_failure` only. A schema MUST
reject any other value. Retrying after a genuine Response is strictly prohibited
(Volume III).

**QualityGate**
```
properties:
  name:                { type: string, minLength: 1 }               # REQUIRED
  aggregate:           { type: string, minLength: 1 }                # REQUIRED
  threshold:           { oneOf: [number, object] }                   # REQUIRED
  compare_against:     { type: string }                              # OPTIONAL
  on_failure:          { type: string, enum: [block_release, warn] } # REQUIRED
  override_requires:   { type: string }                              # OPTIONAL
```

## B.3 — Cross-Type Validation Rules

The following rules cannot be expressed within a JSON Schema alone and MUST be enforced
by a conformant implementation at configuration load time:

| Rule | Source | Description |
|---|---|---|
| Independent Oracle — identity | Volume I, Ch. 3 | A JudgeConfig's `model` MUST NOT be identical to the Environment's `model_version` (same weights/decision process as the subject). |
| Independent Oracle — family | Volume I, Ch. 3 | A JudgeConfig's `model` SHOULD NOT be from the same model family as the Environment's `model_version`, where this can be avoided. |
| Contract non-empty | Volume VII | A Contract with zero Constraints and zero Expectations is invalid. |
| Expectation Oracle exclusivity | Volume VII | Exactly one of `judge`, `multi_judge`, `human_reviewer` MUST be present on an Expectation; `confidence_threshold` is REQUIRED for the first two and OPTIONAL for the third. |
| Dataset version immutability | Volume IV | Two configurations referencing the same Dataset name + version MUST resolve to identical rows. |
| Retry scope | Volume III | RetryConfig MUST NOT trigger on Result-level failures, only infrastructure failures. |
| Baseline reproducibility | Volume X | A Baseline MUST reference a Dataset version and Contract version that are still recoverable. |
| Composition conflict surfacing | Volume VII | When `extends` produces conflicting clause values, the implementation MUST surface the conflict, not silently resolve it. |
| Multi-Judge purpose consistency | Volume VI | An independence-mode MultiJudge with judges from the same model family SHOULD produce a warning. |
| Result disposition validity | Appendix C §C.7 | `verdict` MUST be `null` when `disposition` is `awaiting_review` or `oracle_unavailable`, and MUST be `pass` or `fail` otherwise. `confidence` MUST NOT be bare `null` under any disposition. |
| Deletion referential integrity | Appendix C §C.8 | `DELETE` on an Environment, Dataset, or Contract still referenced by a Baseline, Snapshot, or Report MUST be rejected or preserved as a frozen record, never silently broken. |

## B.4 — Extensibility

A conformant schema MAY define additional properties beyond those specified here,
provided:

1. Additional properties do not conflict with the semantics of specified properties.
2. Additional properties are clearly namespaced or prefixed to avoid collision with
   future AQEF specification revisions.
3. A configuration that uses only specified properties remains valid under the
   extended schema.
